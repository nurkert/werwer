# Entscheidungen

Log der Projektentscheidungen, neueste oben.

| Datum | Entscheidung | Begründung |
|---|---|---|
| 2026-10-25 | **Domain `whowolf.de`**, **App-ID `de.nurkert.whowolf`**, QR-Link `https://whowolf.de/join?room=…&lan=…` | Domain gesichert; App-ID nach Wunsch des Eigentümers; ein Link-Format, das heute die App und später Browser/Server verstehen |
| 2026-10-25 | **MVP zuerst:** lokal im WLAN, Rollen Dorfbewohner/Werwolf/Seherin, QR-Beitritt in der App, Tischkreis, Wolfsspur v1; veröffentlicht als **GitHub-Release + Website**. Server, Browser-Beitritt und Stores erst danach; Server ganz zum Schluss, aber von Anfang an mitgedacht (siehe ROADMAP „Von Anfang an mitdenken“) | Schnellster Weg zu echten Testrunden und einem Release; Wolfsspur ist das Alleinstellungsmerkmal und muss früh am Tisch getestet werden |
| 2026-10-25 | **Wolfsspur** ersetzt „Knurren nur auf Werwolf-Handys“: Spur kommt auf dem Werwolf-Handy **oder beim Sitznachbarn**. Öffentliche Regel „Spur bei X → Werwolf auf X oder daneben“. Sitzordnung nötig. Spursystem allgemein für alle Nachtaktionen (z. B. Eulenspur der Seherin). Details in NIGHT_SOUNDS.md | Dorfbewohner bekommen private Hinweise und wollen laut spielen, Werwölfe können sich durch Stummschalten nicht ganz schützen; wer die Spur hört, ist selbst verdächtig, also Diskussion statt Auflösung |
| 2026-10-25 | **Positionierung über die Kombination**, nicht „erste App mit eigenem Handy“ (siehe MARKET.md); keine Werbung, kein Abo, kein Konto | Marktanalyse: Die Nische ist besetzt, aber nur von kleinen Apps mit Lücken. Realistisches Ziel 10K–100K Downloads über einige Jahre |
| 2026-10-25 | **Idee aufgenommen: verräterische Wolfsgeräusche** + Morgen-Gähnen auf jedem Handy (optionaler Modus, bewusste Ausnahme von der Anti-Tell-Regel) | Neue, physische Deduktionsebene am Tisch, die es so nur mit „jeder hat sein Handy“ gibt |
| 2026-10-25 | **Tag-Bildschirm** zeigt nur, wer lebt (und ob man selbst lebt), dann dimmen | Handys weg, Gesichter lesen ist der Kern des Spiels |
| 2026-10-25 | **Erzähler optional:** App erzählt (Standard) oder Mensch erzählt, App zählt | Manche Gruppen lieben einen menschlichen Erzähler |
| 2026-10-25 | **Nacht-Soundscape auf allen Geräten**, teils mit echten Hinweisen; Geräusche nie direkt an Rolle/Aktion des Besitzers gekoppelt | Atmosphäre „von überall“, neue Spielebene, ohne Tells |
| 2026-10-25 | **Rejoin mit vollem Status und Beitritt während der Partie**; Spielleiter ist ein normaler Spieler; Server als Spielleiter später möglich | Ausfälle dürfen kein Spiel kaputt machen; Host-Logik bleibt deshalb Flutter-frei |
| 2026-10-25 | **Spiel läuft immer beim Host, Server ist nur Relay** (ersetzt „Server ist autoritativ“). Gemischtes Spiel: Spieler im WLAN direkt am Host, Spieler von außen über den Server. QR-Code des Spielleiters führt auf die Server-Webseite (im Browser mitspielen oder App installieren). Offizieller Server voreingestellt, eigener in den Einstellungen, keine Abfrage im Onboarding | Eine einzige Spiellogik für lokal, gemischt und online. Server bleibt dumm, billig und leicht selbst zu hosten, keine Spieldaten auf dem Server. Host verbindet sich ausgehend, daher keine Probleme mit Routern/NAT |
| 2026-10-25 | Name **Whowolf** statt „Werwer“ | Gleiches Wortspiel („Who? Wolf“ = „Wer? Wer?“), aber international verständlich und überall gleich aussprechbar. „Werwer“ lag mit „Werw…“ nah an **Werwörter** (Ravensburger) bzw. **Werewords** (Bezier Games), beides Werwolf-Spiele mit App. Websuche fand kein Spiel/keine App „Whowolf“; Registerprüfung steht noch aus. Repo umbenannt in `nurkert/whowolf` |
| 2026-10-25 | **Start: nur Flutter-App, lokal im gleichen WLAN, ohne Server.** Ein Gerät ist Host und spielt intern die Rolle des autoritativen Servers, die anderen verbinden sich per WebSocket im LAN. So plattformübergreifend wie möglich (Android, iOS, macOS, Windows, Linux; Web nur als beitretender Client, siehe ARCHITECTURE). | Schnellster Weg zu einer spielbaren Runde am Tisch, keine Hosting-Kosten. Die Architektur bleibt so geschnitten, dass später ein echter Server **ohne Umbau** dazukommt: Host-Logik und Transport sind getrennt, das Protokoll ist dasselbe. |
| 2026-10-25 | ~~Name **Werwer**~~ (ersetzt durch Whowolf) statt „Lycan“ | Wortspiel „Wer? Wer?“ + Werwolf, einzigartig, gut verfügbar; „Lycan“ ist im Genre schon belegt („Lycan Master“, „Lycans“). Repo umbenannt in `nurkert/werwer` |
| 2026-10-25 | Doku/Wiki im Repo (`website/`), nicht im GitHub-Wiki | Versioniert, Teil von Pull Requests, im App-Style gestaltbar |
| 2026-10-25 | ~~Server ist **autoritativ**~~ (ersetzt: Host ist autoritativ, Server ist Relay) | Kein Schummeln, Clients sehen nur ihre eigenen Infos |
| 2026-10-25 | Server in **Dart**, Regeln in gemeinsamem Paket `game_core` | Regeln nur einmal schreiben, von App und Server gemeinsam genutzt |
| 2026-10-25 | **Self-Hosting per Docker** + offizieller Server | Open-Source-Gedanke, jeder kann eigenen Server betreiben |
| 2026-10-25 | **Flutter** als primäre App, inkl. **Flutter Web** | Eine Codebasis für alle Plattformen, Beitritt im Browser ohne Installation |
| 2026-10-25 | **Monorepo** `nurkert/whowolf` (öffentlich) | App, Server, Website und Doku an einem Ort |
| 2026-10-25 | Lizenz **Apache 2.0** | Store-kompatibel, permissiv, mit Patentlizenz |
| 2026-10-25 | ~~Name **Lycan**~~ (ersetzt durch Werwer) | Kurz, international, eigene Identität; Markenprüfung noch offen |
| 2026-10-25 | Konzept: vor Ort zusammen, **jeder mit eigenem Gerät**, **App als Erzähler** | Kein Spielleiter nötig, keine Tells, Regeln automatisch |
